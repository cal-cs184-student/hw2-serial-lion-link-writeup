Section I: Bezier Curves and Surfaces

Part 1: Bezier curves with 1D de Casteljau subdivision

De Casteljau's algorithm is a recursive method to evaluate Bezier curves at a given parameter value t by repeated interpolation. Given n control points, the algorithm produces n-1 new intermediate points by linearly interpolating between consecutive control points. Repeating this process recursively we eventually obtain a single remaining point. That point is the point on the Bezier curve corresponding to the parameter value t. Sweeping t from 0 to 1 builds the entire curve.
In our implementation, the function BezierCurve::evaluateStep() evaluates one level of this recursive process by looping over each consecutive pair of points: points[i-1] and points[i] and pushes the interpolated point to a new vector of points. Calling this function repeatedly builds the entire curve.

Part 2: Bezier surfaces with separable 1D de Casteljau

De Casteljau's algorithm extends to Bezier surfaces through the use of separable 1D evaluations. Each row of the grid can be treated as a Bezier curve, and the algorithm can be applied to each row. After evaluating each row at a given parameter value u, we produce a set of contron points for a new Bezier curve in the v direction. Evaluating the curve at v, gives the point on the surface B(u, v).
We implemented this with three functions. evaluateStep() performs one level of the algorithm on a list of 3D points. evaluate1D() fully evaluates a 1D Bezier curve by repeatedly calling evaluateStep(). Finally, evaluate() valls evaluate1D() on each row of the grid with parameter u, collects the resulting points and calls evaluate1D() again on these points.

Section II: Triangle Meshes and Half-Edge Data Structure

Part 3: Area-weighted vertex normals

To compute the area-weighted normal at a vertex, we walk through all the faces incident to the vertex using the half-edge data structure. Repeatedly moving to h->twin()->next() allows us to rotate around the outgoing half-edges from the vertex. For each face, we compute the cross product of the two edges of the traingle to get the triange area weighted normal. We sum these normals and normalize the result to get the area-weighted vertex normal.

Part 4: Edge flip

To flip an edge, we first check that the edge is not a boundary edge. If so, then we leave everything unchanged. Otherwise, we store the two adjacent triangles b->c->a and c->b->d, we sotre all six interior half-edges, we store both faces, and all four vertices. We reuse the existing elements instead of allocating new ones. The edge's two halfedges become the new diagonal starting at a and d. The next() pointers are then changed to two new ccw triangles a->d->c and d->a->b. dc and ab switch triangles, so they get their face() pointers updated. Finally, every vertex and face is pointed at a halfedge that is still incident to it.
Our main debugging trick was drawing the quadrilateral before and after the flip with every element labeled and storing all the variables before any changes were made.
Our main bug was forgetting to update the face() pointers of the halfedges dc and ab. The next() pointers were correct, but the two halfedges were still pointing to the old faces. This caused the halfedge data structure to be inconsistent and some triangles started to disappear after multiple flips.

Part 5: Edge split

For the edge split operation, we introduce a new vertex m and assign the old bc edge to be the new mc edge. We then introduce the new mesh elements from m to the remainding vertices, such as the new halfedges, edges, and faces. We also update all the existing mesh elements to account for the new mesh elements. There was not an eventful debugging journey, we just iterated through all the mesh elements before and after the split to make sure all elements were updated properly.

Part 6: Loop subdivision for mesh upsampling

We implemented the loop subdivision algorithm in five passes, following the staff suggested steps outlined in the function. First, we compute the new position of each original vertex using the loop subdivision formula: (1 - n * u) * original_position + u * original_neighbor_position_sum. For this, we loop through all the neighboring vertices of the original verted and sum their positions. Second, we compute the position of the new vertices by using the vertices A, B, C, and D: 3/8 * (A + B) + 1/8 * (C + D). Third, we split every original edge, looping over a vector of the original edges collected beforehand to avoid modifying the vector of edges while iterating. New vertices are marked new and new edges as well inside of splitEdge. Fourth, we loop over all the edges again and flip edges that connect an old vertex and a new vertex. Finally, we loop over all the vertices and copy their new positions. Originally our triangulation pattern was wrong, so we disabled the this last step to check the traingulation pattern on the cube on its own.
When we do loop subdivision, we repalce every verted with a weighted average of its neighbors. This means that sharp edges and coners get rounded and the mesh shrinks slighly each iteration. Pre-splitting edges near a sharp feature places extra vertices close to it, so the averaging acts over a shorter distance and the feature stays sharper.
The cube in cube.dae triangulates each face with a single diagonal. This means that different corners end up with different number of neighbors. The loop subdivision formula depends on number of neighbors so different corners behave differently. Each iteration, the asymmetry accumulates and the cube becomes more distorted. If you presplit the edges of the cube, then each corner hs the same number of neighbors, and the cube subdivides symmetrically.
